A continuación describo la aplicación (aunque indique que algo “se hará” de una forma concreta, puedes cuestionarlo o proponer mejoras):

1. Características principales
- Los competidores deben crear una cuenta para subir sus capturas, con opción de registro mediante plataformas como Google.
- La aplicación tendrá, al iniciar, dos botones principales (crear torneo / unirse a torneo) y un icono de usuario para acceder al perfil.
- La persona que crea un torneo será la administradora de ese torneo.
- Las personas que se unen a un torneo serán participantes.
- Los participantes podrán subir capturas mediante una interfaz específica.
- En el envío de capturas:
    - Selección de la especie del pez desde una lista desplegable.
    - Subida de foto del pez.
- Los participantes podrán ver una tabla de clasificación, idealmente en tiempo real, basada en puntos.
- El administrador:
    - Podrá ver la clasificación.
    - Tendrá un sistema de revisión (por ejemplo, un RecyclerView tipo “bandeja de tareas”) para aprobar o denegar capturas y la capacidad de corregirlas (por si la foto esta bien pero los datos mal) además de una forma en la que devolver un mensaje del por que se ha denegado una captura (este mensaje lo deberían de poder ver los competidores, quizás un recycler view en la pantalla donde suben capturas con las capturas y su estado aceptado-pendiente-denegado + mensaje).
    - Recibirá una notificación cuando haya capturas pendientes de validar.
- En el perfil, los usuarios podrán ver:
    - Historial de capturas.
    - Estadísticas por especie capturada.

2. Estructura técnica:
- La aplicación se desarrollará en Kotlin usando Android Studio.
- Si no hay una opción claramente mejor, el proyecto partirá de una Empty Views Activity (puedes sugerir alternativas).
- Se usará una base de datos gratuita en la nube, preferiblemente Firebase.
- Deberá existir una separación clara entre:
    - Frontend
    - Backend / lógica de negocio
    - Base de datos
- La app debe:
    - Tener un diseño intuitivo y fácil de navegar.
    - Usar componentes visuales claros.
    - Implementar tanto front como backend, incluyendo:
        - Subida de imágenes.
        - Cálculo y actualización de puntuaciones.
- Para el sistema de notificaciones, valora el uso de Firebase Cloud Messaging (FCM) e indica si es la mejor opción.
