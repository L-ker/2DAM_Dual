==================================================
OBJETIVO DEL PROYECTO
==================================================

La aplicación se llama Full Fishing.

Es una aplicación móvil multiplataforma enfocada exclusivamente en la gestión profesional de torneos de pesca deportiva.

La aplicación NO debe enfocarse como red social.

El objetivo principal es:
- digitalizar la gestión de competiciones
- facilitar la validación de capturas
- automatizar clasificaciones
- mejorar el trabajo de jueces y participantes

La aplicación debe ser:
- funcional
- rápida
- intuitiva
- clara
- usable en exteriores
- usable con mala conexión
- preparada para torneos reales

==================================================
ROLES DE USUARIO
==================================================

Existen dos roles:

PARTICIPANTE
Puede:
- unirse a competiciones
- registrar capturas
- ver clasificaciones
- consultar historial

JUEZ
Puede:
- crear competiciones
- crear ligas
- validar capturas
- gestionar equipos
- configurar reglas
- modificar capturas
- revisar clasificaciones

Un juez puede participar en otras competiciones.
Nunca debe participar en una competición propia.

==================================================
COMPETICIONES
==================================================

Una competición puede tener:
- múltiples días
- horarios
- especies permitidas
- cupos máximos
- ubicación
- radio permitido
- modalidad individual o por equipos

Estados posibles:
- CREATED
- ACTIVE
- REVIEW
- FINISHED

==================================================
SISTEMA DE CAPTURAS
==================================================

Las capturas deben realizarse desde la aplicación.

No deben permitirse imágenes desde galería salvo decisión explícita del usuario.

Cada captura debe almacenar:
- usuario
- competición
- especie
- timestamp
- ubicación GPS
- archivo multimedia
- estado de validación

El sistema debe comprobar:
- horario válido
- ubicación válida
- competición activa

==================================================
MODO OFFLINE
==================================================

La aplicación debe funcionar parcialmente sin internet.

Las capturas deben:
- almacenarse localmente
- mantenerse aunque la app se cierre
- sincronizarse automáticamente al recuperar conexión

La estrategia offline debe diseñarse correctamente antes de implementarse.

Debes priorizar soluciones simples y fiables.

==================================================
VALIDACIÓN DE CAPTURAS
==================================================

Los jueces deben poder:
- aprobar
- rechazar
- modificar especie
- modificar tamaño
- añadir comentarios

La clasificación debe recalcularse automáticamente.

==================================================
CLASIFICACIONES
==================================================

La aplicación debe soportar:
- clasificación individual
- clasificación por equipos
- clasificación de ligas

Las clasificaciones deben actualizarse automáticamente cuando:
- se valida una captura
- se modifica una captura
- se elimina una captura

==================================================
OPTIMIZACIÓN DE FIREBASE
